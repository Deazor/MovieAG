# MovieAG

Локальный агрегатор аниме: ищет тайтл сразу во всех источниках из `sources.yaml`, склеивает результаты по ID Shikimori и показывает все озвучки в одном плеере.

Стек: .NET 10, ASP.NET Core, EF Core (PostgreSQL и SQLite), Quartz.NET, Angular, hls.js, WinForms + WebView2, xUnit.

Есть две версии на одном коде:

| | Desktop | Веб |
|---|---|---|
| Запуск | Один `MovieAG.exe`, ничего ставить не нужно | Docker, .NET SDK и Node |
| База | SQLite в `%LOCALAPPDATA%\MovieAG` | PostgreSQL в контейнере |
| Конфиг | `%APPDATA%\MovieAG\sources.yaml` | `sources.yaml` в корне репозитория |
| Платформа | Windows 10/11 x64 | Любая с браузером |

> **Предупреждение.** Проект создан для личного использования и обучения. Приложение не хранит и не распространяет видео: контент и рекламу предоставляют сторонние сервисы, которые вы сами указываете в конфиге. За соблюдение авторских прав и условий этих сервисов отвечает пользователь.

## Desktop-версия

Сборка одного exe (нужны .NET SDK 10 и Node 24, результат появится в `artifacts\desktop\MovieAG.exe`):

```powershell
.\scripts\publish-desktop.ps1
```

Для запуска на другом ПК достаточно скопировать `MovieAG.exe`.

- **Первый запуск:** приложение создаёт `sources.yaml` из примера и открывает экран «Источники», где конфиг можно сразу отредактировать.
- **Данные:** база и профиль встроенного браузера лежат в `%LOCALAPPDATA%\MovieAG`, конфиг в `%APPDATA%\MovieAG`. Переменная окружения `MOVIEAG_HOME` переносит всё в одну указанную папку.
- **WebView2:** окно использует Microsoft Edge WebView2, который уже есть в Windows 10/11. Если его нет, приложение подскажет, где скачать.
- **Предупреждение Windows:** exe не подписан, поэтому при первом запуске SmartScreen может показать «Неизвестный издатель»: «Подробнее» → «Выполнить в любом случае».
- **Токены:** `dotnet user-secrets` в exe не работают, токен источника задаётся переменной окружения или прямо в `sources.yaml`.

## Веб-версия

Нужны .NET SDK 10, Node 24 и Docker.

Скопируйте пример конфига и укажите в `sources.yaml` свои источники:

```bash
cp sources.example.yaml sources.yaml
```

```bash
docker compose up -d --wait
```

```bash
dotnet run --project src/MovieAG.Api --launch-profile http
```

```bash
npm --prefix client install
```

```bash
npm --prefix client start
```

Приложение откроется на http://localhost:4200, Swagger на http://localhost:5140/swagger. Миграции применяются при старте API.

## Источники

Список хранится в `sources.yaml`, его можно менять в файле или на экране «Источники». Этот файл не попадает в git, в репозитории лежит только `sources.example.yaml`. Порядок задаёт приоритет.

| Поле | Значение |
|---|---|
| `id` | Уникальное имя; по нему же выбирается адаптер |
| `type` | `balancer`, `api` или `site` |
| `url` | Базовый адрес API |
| `token` | Токен, обычно ссылка `${NAME}` на настройку |
| `adapter` | Имя адаптера, если отличается от `id` |
| `enabled` | `false` выключает источник |

Адаптеры есть для `anilibria` (без токена, HLS), `yummy` (без токена, iframe разных плееров) и `kodik` (iframe, токен необязателен). Для остальных `id` экран покажет «Нет адаптера».

У `yummy` поиск не называет озвучки: их полный список появляется в карточке тайтла. Если получите client_id на yummyani.me/dev/applications, укажите его в поле `token`.

Без `token` источник `kodik` берёт публичный токен из скрипта плееров `kodik-add.com/add-players.min.js` (как `getPublicToken` в kodikwrapper). Токен кэшируется на 6 часов, а если Kodik его отвергнет, скачивается заново и запрос повторяется один раз.

Публичный токен принимает только `/get-player`, поэтому без своего токена Kodik работает в упрощённом режиме: в поиске и новинках его нет, тайтлы берутся из каталога, у тайтла один вариант «… и другие (выбор в плеере)», а озвучку и сезон выбирают в самом плеере Kodik. Число серий берётся из каталога. Собственный токен включает полный режим; его лучше хранить в user-secrets, а не в файле:

```bash
dotnet user-secrets set KODIK_TOKEN "ваш-токен" --project src/MovieAG.Api
```

## Фильмы

Раздел «Фильмы» работает отдельно от аниме: карточки адресуются IMDb ID (`tt1254207`), настройки лежат в секции `movies` файла `sources.yaml`.

Метаданные берутся из TMDB. Токен задаётся переменной `TMDB_TOKEN` (подходят и токен чтения, и короткий API-ключ); без него карточки строятся из полей библиотеки:

```bash
dotnet user-secrets set TMDB_TOKEN "ваш-токен" --project src/MovieAG.Api
```

Адаптер `library` проигрывает HLS-потоки, перечисленные в конфиге. Несколько записей с одним `imdbId` становятся вариантами просмотра.

| Поле | Значение |
|---|---|
| `imdbId` | IMDb ID вида `tt1234567` |
| `name` | Название, обязательное |
| `url` | Адрес HLS-плейлиста, сервер должен разрешать CORS |
| `label` | Подпись варианта просмотра, по умолчанию «Оригинал» |
| `license` | Лицензия, показывается под плеером |
| `originalName`, `year`, `description`, `posterUrl`, `genres` | Необязательные метаданные |

### Kodik для фильмов

```yaml
movies:
  sources:
    - id: kodik-movies
      adapter: kodik
      type: balancer
      token: ${KODIK_TOKEN}   # можно не указывать
```

Без своего токена используется публичный, а он находит по IMDb ID только аниме-фильмы. Поиск тогда понимает только IMDb ID (`tt0245429`), новинок нет, озвучка выбирается в плеере. Название и постер подставляет TMDB, если задан `TMDB_TOKEN`, иначе карточка подписана IMDb ID.

С собственным токеном включаются поиск по названию, новинки и отдельный вариант просмотра на каждую озвучку; в конфиге ничего больше менять не нужно. Этот режим собран по описанию API и с настоящим токеном ещё не проверялся.

### Alloha для фильмов

```yaml
movies:
  sources:
    - id: alloha
      type: balancer
      token: ${ALLOHA_TOKEN}
      latest: 24   # сколько новинок показывать на странице «Фильмы», от 1 до 40
```

Нужен собственный токен из кабинета Alloha: открытого токена, как у Kodik, у неё нет, и без токена источник показывает «Нужен токен». Поиск работает по IMDb ID и по названию, у фильма отдельный вариант просмотра на каждую озвучку. Сериалы на странице фильмов не показываются.

Новинки берутся из списка Alloha, отсортированного по дате добавления (`list=movie&order=date`). В нём попадаются и старые фильмы, добавленные недавно, поэтому показываются только фильмы этого и прошлого года. Без `latest` их до 24. Карточки идут в порядке источников, поэтому чтобы новинки были наверху, поставьте `alloha` выше библиотеки фильмов. Фильмы без IMDb ID в список не попадают. Плеер Alloha может проверять сайт, на котором встроен: если вместо видео ошибка, добавьте адрес приложения в настройках кабинета. Ссылка на плеер содержит токен, как и у любого встраиваемого плеера Alloha.

Новый источник фильмов: реализуйте `IMovieSource` и зарегистрируйте адаптер в словаре `MovieAdapters` в `SourceRegistry`.

## Каталог: жанры, годы и сортировка

На страницах «Каталог» (аниме) и «Фильмы» есть панель фильтров: жанр, годы выхода «с» и «по», сортировка (сначала новые, по рейтингу, по популярности). Выдача идёт постранично, все параметры хранятся в адресе (`/search?genre=22&from=2015&to=2020&sort=rating&page=2`), поэтому страницу можно добавить в закладки. Текст из строки поиска сочетается с фильтрами.

| | Аниме | Фильмы |
|---|---|---|
| Каталог | Shikimori | TMDB, нужен `TMDB_TOKEN` |
| На странице | 24 | до 20 |
| «Сначала новые» | без анонсов | без ещё не вышедших |
| Текст + фильтры | всё на стороне Shikimori | жанр и годы применяются внутри страницы поиска TMDB, страница может быть короче |

Каталог показывает все тайтлы, а не только те, что есть в ваших источниках: наличие видно на странице тайтла или фильма. Фильмы без IMDb ID в выдачу TMDB не попадают. Без фильтров страницы работают как раньше: «Каталог» с текстом ищет по источникам с озвучками, «Фильмы» показывают новинки и «Продолжить просмотр».

На карточках показываются оценки: у аниме — Shikimori, у фильмов — IMDb и КП (их отдают Alloha и Kodik со своим токеном) и TMDB (если задан `TMDB_TOKEN`, при 10 голосах и больше). Оценка 8 и выше выделена цветом.

REST API Shikimori у новых тайтлов вместо постера отдаёт заглушку, поэтому недостающие постеры добираются одним запросом к GraphQL API Shikimori. Карточку тайтла без постера или оценки приложение перепроверяет раз в час, а не раз в неделю.

Без токена TMDB вместо панели фильтров на странице «Фильмы» будет подсказка. Бесплатный токен выдаётся в настройках аккаунта на themoviedb.org (раздел API).

## История просмотра

Для каждого тайтла сохраняются серия, озвучка, источник и позиция в серии. Встроенные плееры сообщают время через `postMessage`, форматы описаны в `client/src/app/core/player-bridge.ts`.

| Плеер | Сохранение времени | Автоперемотка |
|---|---|---|
| HLS (AniLibria) | Да | Да |
| Kodik | Да | Да |
| CVH | Да | Да, после рекламы |
| Aksor | Да | Нет, приложение подсказывает время для ручной перемотки |
| Alloha | Нет | Нет |

## Новый источник

1. Реализуйте `IAnimeSource` в `src/MovieAG.Infrastructure/Sources`.
2. Зарегистрируйте адаптер в словаре `Adapters` в `SourceRegistry`.
3. Добавьте запись в свой `sources.yaml`.

## Изменение модели данных

У каждой базы свой набор миграций, поэтому после изменения сущностей нужны две команды (`Имя` замените своим):

```bash
dotnet ef migrations add Имя -p src/MovieAG.Infrastructure -s src/MovieAG.Api -o Persistence/Migrations --context AppDbContext
```

```bash
dotnet ef migrations add Имя -p src/MovieAG.Infrastructure -s src/MovieAG.Api -o Persistence/SqliteMigrations --context SqliteDbContext
```

В выдачу попадают только тайтлы с ID Shikimori: по нему работает склейка.

## Безопасность

У API нет авторизации: приложение рассчитано на одного пользователя и слушает только `localhost`. Перед публикацией в сеть нужно добавить аутентификацию. Пароль в `compose.yaml` предназначен только для локальной разработки.
